# Next.js

Next.js 是一个基于 React 的框架，提供了服务器端渲染（SSR）和静态站点生成（SSG）的功能，使得构建高性能的 React 应用变得更加容易。

## 快速启动

使用 Next.js 脚手架快速创建一个新的 Next.js 项目：

```bash
npx create-next-app@latest
```

使用 `npm run dev` 命令启动开发服务器，默认端口为 0.0.0.0:3000：

```bash
npm run dev
```

## 目录结构

Next.js 的默认目录结构如下：

```
my-next-app/
├── app/
|   ├── page.tsx
|   ├── layout.tsx
|   └── ...
├── components/
├── public/
├── tsconfig.json
├── package.json
├── next.config.ts
└── ...
```

## 页面路由

相比较 React 中通过 `<Route path="/about">` 定义路由，Next.jsz 直接利用文件夹路径作为路由。

Next.js 使用文件系统作为路由机制。每个在 `app` 目录下的 `.tsx` 文件都会自动成为一个路由。例如，`app/page.tsx` 对应根路径 `/`，而 `app/about.tsx` 对应路径 `/about`。

常见的一些页面组件包括：

- `page.tsx` 页面入口
- `layout.tsx` 页面布局组件，所有页面共享，切换路由时不会重载组件
- `template.tsx` 页面模板组件，每次访问都会重新渲染
- `loading.tsx` 加载状态组件，路由切换时显示
- `error.tsx` 错误状态组件，路由切换失败时显示
- `not-found.tsx` 404 页面组件，访问未定义路由时显示

以及还能通过 `app/api` 目录定义 API 接口，例如通过 `app/api/v1/test.ts` 定义了一个 API 接口：

- `route.ts` API 路由，处理后端请求

文件夹结构也有一些特殊的命名约定：

- `[param]` 动态路由参数，例如 `app/blog/[id].tsx` 或者 `app/blog/[id]/page.tsx` 对应 `/blog/:id`
- `[[param]]` 可选的动态路由参数，例如 `app/blog/[[id]].tsx` 对应 `/blog` 和 `/blog/:id`
- `[...slug]` catch-all 路由参数，例如 `app/docs/[...slug].tsx` 对应 `/docs/*`
- `[[...slug]]` 可选的 catch-all 路由参数，例如 `app/docs/[[...slug]].tsx` 对应 `/docs/*`
- `(...)` 分组路由，例如 `app/(admin)/dashboard.tsx` 对应 `/dashboard`，但在 `app/(admin)/settings.tsx` 中对应 `/settings`

## 前端渲染类别

- CSR 客户端渲染
- SSR 服务器端渲染
- SSG 静态站点生成
- ISR 增量静态再生
