# LatticeCNN 题解

## 1. 题目信息 / 目标 / 环境

- 题目附件位于 `task/`，包含 `task.py`、`inputs.npy`、`outputs.npy`、`public.json`、`cipher.bin`。
- 目标是从公开的 CNN-like 特征抽取流程中恢复隐藏整数向量 `secret_s`，再利用它解出 `cipher.bin` 中的 flag。

## 2. 初始判断与题型路由

读 `task.py` 后可以看到，所谓的 “tiny CNN-like model” 并不是要训练的模型，而是一个完全公开、可复现的特征提取器：

1. 对 `6x6` 输入分别做两次 `3x3` 卷积。
2. 过 `ReLU`。
3. 做 `2x2` 平均池化。
4. 拼成 8 维向量后，再乘公开的 `8x8` 矩阵 `MIX`，得到系数向量 `a_i`。
5. 最后输出满足 `b_i = <a_i, s> + e_i (mod q)`，其中 `q = 65537`，`e_i ∈ [-2,2]`。

这一步已经把题型钉死成了一个小维度 LWE / 带小噪声模线性恢复问题，所以路由到 `ctf-crypto` 即可，不需要走 AI 训练或模型逆向。

## 3. 关键试探与排除过程

先按源码把 `feature(x)` 完整复现出来，然后用 `inputs.npy` 生成全部 24 个公开向量 `a_i`。得到的矩阵 `A` 形状为 `24x8`，秩为 `8`，说明 8 维秘密向量 `s` 在样本数量上是可恢复的。

这里最关键的观察是：未知量只有 8 维，而每条噪声只在 `[-2,2]` 这 5 个值里变化。于是可以选出任意一组模 `q` 下可逆的 `8x8` 子矩阵，对这 8 条方程的噪声做枚举。每猜定一个噪声向量 `e`，就能唯一解出一个候选 `s`，再把它带回全部 24 条方程检查残差是否都落在 `[-2,2]`。

## 4. 决定性线索

这题的规模非常小：

- 未知向量维度是 `8`
- 枚举空间是 `5^8 = 390625`
- 每个候选只要再验证 24 条方程

因此完全没必要一开始就上重型格工具。直接做“小噪声枚举 + 全样本验真”就能在很短时间内得到唯一解。

## 5. 漏洞或核心突破点验证

按上述方法恢复出的唯一候选为：

```text
s ≡ [17, 65525, 9, 65522, 6, 14, 65529, 11] (mod 65537)
```

把它中心化到 `[-q/2, q/2]` 后得到真正更自然的有符号表示：

```text
s = [17, -12, 9, -15, 6, 14, -8, 11]
```

再把这个 `s` 带回所有样本，残差为：

```text
[-1, 1, 2, -1, 2, 2, 0, -2, 1, -1, -1, 2, 0, 2, 1, 1, -1, 2, -1, 1, -2, -2, 1, -2]
```

全部都在题目给出的噪声界 `[-2,2]` 内，因此 `s` 已经被严格验证。

## 6. 利用或恢复路径

恢复 `s` 之后，还需要处理 `cipher.bin`。它的长度是 `48` 字节，正好是 3 个 AES block，因此更像是一个对称加密结果，而不是简单异或。

由于 `s` 只有 8 个整数，直接作为 AES key 长度不够，更合理的方式是“先把 `s` 序列化，再哈希出 16 字节密钥”。对几种常见序列化方式做最小验证后，命中的方式是：

```python
key = sha256(','.join(map(str, s)).encode()).digest()[:16]
plaintext = AES.new(key, AES.MODE_ECB).decrypt(cipher)
flag = unpad(plaintext, 16)
```

## 7. flag 获取过程

执行上面的解密逻辑后得到：

```text
flag{7ffd71471b67009e1c39cfaa259cf7b2}
```

## 8. 复盘

这题最容易误导人的地方是题面里的 “CNN-like model”。如果先把它当成 AI 题，很容易跑偏到训练、拟合、逆向模型参数这些高成本方向。实际上公开网络只是一个把输入变成 `a_i` 的包装器，真正的核心还是一个低维、小噪声的模线性恢复问题。

更好的 proof 顺序是：

1. 先看网络是不是完全公开、可执行。
2. 如果最后一层只剩线性组合加小噪声，就立刻把它压缩成 LWE/模线性方程。
3. 先用最小规模枚举证明能恢复 `s`，再处理后续密文。
