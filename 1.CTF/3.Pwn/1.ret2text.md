# ret2text

ret2text 是一种利用程序中存在的文本段（.text）来执行攻击的技术。攻击者通过覆盖返回地址，使程序跳转到文本段中的某个位置，从而执行攻击者控制的代码。

例如，攻击者可以在文本段中找到一个合适的指令序列（如 `.text:4012FE lea rdi, command ; "/bin/sh"`），然后覆盖返回地址，使程序跳转到这个指令序列的位置。这样，攻击者就可以执行任意命令（如 `/bin/sh`），从而获得系统的控制权。

## 利用

首先，需要找到文本段中合适的指令序列。可以使用工具 `IDA` 分析程序，找到包含攻击者需要的指令的地址。比如找到如下指令：

```
.text:00000000004012F6 ; void __cdecl backdoor()
.text:00000000004012F6                 public backdoor
.text:00000000004012F6 backdoor        proc near
.text:00000000004012F6 ; __unwind {
.text:00000000004012F6                 endbr64
.text:00000000004012FA                 push    rbp
.text:00000000004012FB                 mov     rbp, rsp
.text:00000000004012FE                 lea     rdi, command    ; "/bin/sh"
.text:0000000000401305                 call    _system
.text:000000000040130A                 nop
.text:000000000040130B                 pop     rbp
.text:000000000040130C                 retn
.text:000000000040130C ; } // starts at 4012F6
```

通过这段汇编可以确定这个后门函数 `backdoor` 的地址是 `0x4012F6`，并且它会调用系统函数 `_system` 来执行 `/bin/sh`。

然后，需要找到存在栈溢出漏洞的函数，然后确定该变量地址到栈顶的偏移量。例如

```
.text:00000000004011B6 ; int __cdecl vuln()
.text:00000000004011B6                 public vuln
.text:00000000004011B6 vuln            proc near
.text:00000000004011B6 ; __unwind {
.text:00000000004011B6                 endbr64
.text:00000000004011BA                 sub     rsp, 28h
.text:00000000004011BE                 mov     rax, qword ptr [fs:28h]
.text:00000000004011C7                 mov     qword ptr [rsp+18h], rax
.text:00000000004011CC                 xor     eax, eax
.text:00000000004011CE                 mov     rax, qword ptr [rsp+18h]
.text:00000000004011D2                 xor     rax, qword ptr [fs:28h]
.text:00000000004011D7                 jnz     short loc_4011E0
.text:00000000004011D9                 add     rsp, 28h
.text:00000000004011DD                 retn
.text:00000000004011E0 ; ---------------------------------------------------------------------------
.text:00000000004011E0 loc_4011E0:                             ; CODE XREF: vuln+21j
.text:00000000004011E0                                         ; vuln+2Fj
.text:00000000004011E0                 call    __stack_chk_fail
.text:00000000004011E5                 jmp     short loc_4011E0
.text:00000000004011E7 ; } // starts at 4011B6
```

通过分析可以发现，在 `vuln` 函数中存在一个栈溢出漏洞，而且如果想要利用溢出去试图覆盖返回地址，先得确定这个变量地址到基址的偏移量，如下图

```
-0000000000000004 var_4           dd ?
+0000000000000000  s              db 8 dup(?)
+0000000000000008  r              db 8 dup(?)
```

可以看出，变量 `var_4` 的地址到栈顶的偏移量是 `0x4`，然而实际上栈帧中栈帧基址 `rbp` 指向的是 `old rbp` 的位置，再向上偏移 `0x8` 的位置才是返回地址的位置，因此需要在偏移量 `0x4` 的基础上再加上 `0x8`，最终得到的偏移量是 `0xC`

```
高地址
      |
0x2008│  返回地址
0x2000│  old rbp
0x1FFC│  var_4
      ↓
低地址
```

### 栈平衡

`retn` 的动作固定：`rip = [rsp]`，然后 `rsp += 8`。所以“栈平衡”可以理解成：你让它每次从栈上取走的 8 字节，都是一个你想跳到的地址。

下面只展示两种最常见结果（用的名字和“栈对齐”一致：`backdoor()` / `父函数..`）。

#### 不平衡: backdoor() 返回时崩溃

目标仍然是跳进 `backdoor()`，但栈上没有给 backdoor 准备好“返回地址”。结果往往是：能进 backdoor，甚至能执行到 `system`，但 backdoor 一 `retn` 就崩。

`vuln()` 执行 `retn` 前（注意 0x2008 这格是垃圾值）：

```
高地址
      |
0x2008│  垃圾值/未初始化   <-- 这里本该放 父函数..
0x2000│  backdoor()       <-- rsp
      ↓
低地址
```

`vuln()` 执行 `retn` 后（进入 backdoor，但 backdoor 的返回地址已经错了）：

```
高地址
      |
0x2008│  垃圾值/未初始化   <-- rsp（backdoor() 将来的返回地址，必然不靠谱）
0x2000│  backdoor()
      ↓
低地址
```

`backdoor()` 执行到 `retn` 后：CPU 会把“垃圾值”当作 `rip` 跳过去，程序通常直接崩溃。

#### 平衡: backdoor() 能正常返回

你把 `backdoor()` 以及它的“返回地址”都摆好了，所以 `backdoor()` 执行完还能跳回 `父函数..`。

`vuln()` 执行 `retn` 前：

```
高地址
      |
0x2008│  父函数..     <-- backdoor() 结束后 retn 要跳到这里
0x2000│  backdoor()   <-- rsp（vuln() 的 retn 会先跳到这里）
      ↓
低地址
```

进入 `backdoor()` 后：

```
高地址
      |
0x2008│  父函数..     <-- rsp（backdoor() 将来的返回地址）
0x2000│  backdoor()
      ↓
低地址
```

`backdoor()` 执行到 `retn` 后（跳回父函数..）：

```
高地址
      |
0x2010│  （父函数.. 的后续栈数据）  <-- rsp
0x2008│  父函数..
0x2000│  backdoor()
      ↓
低地址
```

#### 怎么手动改成“平衡”

1. 把 `vuln()` 的返回地址覆盖成 `backdoor()`。
2. 在 `backdoor()` 后面再放一格“返回地址”（文中用 `父函数..` 表示），让 `backdoor()` 执行到 `retn` 时有地方跳。
3. 如果你已经做到 1-2 仍然崩溃，常见原因是下面要讲的 **栈对齐**。这时通常会在 `backdoor()` 前额外加一个 `retn` 来调整 `rsp`。

### 栈对齐

在一些平台上例如 x86-64，函数调用要求栈必须按照特定的字节对齐（通常是 16 字节）。这意味着在调用函数之前，必须确保 `rsp` 的值是 16 的倍数，否则可能会导致程序崩溃或者行为异常。

比如，在覆盖返回地址，程序执行到 `retn` 后，如下

```
高地址
      |
0x2008|  父函数..   <-- rsp
0x2000│  backdoor()
      ↓
低地址
```

虽然 `backdoor()` 函数的地址被正确覆盖了并写入了 `rip`，但 `rsp` 的值不是 16 的倍数，于是会导致程序崩溃。

因此可以在 payload 中额外增加一个 retn 指令来调整栈对齐，如下

`retn` 前

```
高地址
      |
0x2008|  backdoor()
0x2000│  retn       <-- rsp
      ↓
低地址
```

`retn` 后，额外写入的 `retn` 指令被加入到 `rip` 中，于是下一步还会再执行一遍 `retn`

```
高地址
      |
0x2008|  backdoor() <-- rsp
0x2000│  retn
      ↓
低地址
```

再一次 `retn` 后，`backdoor()` 写入 `rip`

```
高地址
      |
0x2010|  父函数..   <-- rsp
0x2008|  backdoor()
0x2000│  retn
      ↓
低地址
```

于是此时的 `rsp` 的值是 `0x2010`，是 16 的倍数，程序就不会崩溃了。便能成功执行 `backdoor()` 函数了。
