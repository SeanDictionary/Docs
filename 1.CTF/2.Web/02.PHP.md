# PHP

## 弱 md5

弱 `md5` 在 CTF 里通常不是指真的把 `md5` 撞出了碰撞，而是指 **PHP 弱类型比较导致的“魔术哈希（magic hash）”问题**。

### 原理

- PHP 使用 `==`、`!=` 做比较时，会先尝试做类型转换。
- 如果两个字符串都长得像科学计数法，例如 `0e123456`，PHP 会把它们当成数字比较。
- `0e123456`、`0e999999` 在数值意义上都等于 `0 × 10^n`，也就是 `0`。
- 所以当两个不同字符串的 `md5()` 结果都满足 `0e[0-9]+` 这种形式时，`==` 比较就可能成立。

这类题本质上是：

- `hash` 结果可控；
- 后端用了宽松比较；
- 没有做更严格的类型校验。

### 典型代码

```php
<?php
$a = $_GET['a'];
$b = $_GET['b'];

if ($a != $b && md5($a) == md5($b)) {
    echo $flag;
}
```

这里利用点在于：

- `$a != $b`：要求原始输入不同；
- `md5($a) == md5($b)`：由于使用了 `==`，可以尝试用“魔术哈希”绕过。

### 常见可用字符串

下面这些值经常在题里直接拿来用：

```text
QNKCDZO    -> 0e830400451993494058024219903391
240610708  -> 0e462097431906509019562988736854
```

因此这组参数通常可以直接命中经典题型：

```text
a=QNKCDZO&b=240610708
```

因为：

- `a != b` 成立；
- `md5(a)` 和 `md5(b)` 都形如 `0e...`；
- 在 `==` 下，两边会被当成数值 `0` 比较。

### 常见变种

#### 1. 直接比较 hash 值

```php
if (md5($a) == md5($b))
```

这是最经典的写法。

#### 2. 与固定字符串比较

```php
if (md5($a) == '0e215962017')
```

如果题目把目标字符串写成了看起来像数字的形式，也可能被弱比较绕过。

#### 3. 不止 md5

不只是 `md5()`，只要是返回字符串 hash 的函数，并且后面进入了 `==` 比较，都要考虑同类问题，例如：

- `sha1()`
- `hash()`

核心不在算法本身，而在 **比较方式是否宽松**。

### 做题时的判断关键词

看到下面这些特征时，要优先想到弱比较：

- 代码里出现 `md5()`、`sha1()`、`hash()`；
- 后面跟的是 `==` 或 `!=`，不是 `===`；
- 题目要求“两个参数不同，但校验结果相同”；
- 输入点来自 `$_GET`、`$_POST`、`$_REQUEST`。

## 数组绕过

数组绕过也是 PHP 题里非常高频的一个点，本质是：**开发者以为自己拿到的是字符串，但攻击者通过 `a[]=1` 这种形式传入了数组。**

### 原理

PHP 接收参数时：

```text
?a=1      -> $_GET['a'] = '1'
?a[]=1    -> $_GET['a'] = array(0 => '1')
```

如果后端没有先判断类型，直接把数组送进本该接收字符串的函数，就可能出现：

- 旧版本 PHP：报 `Warning`，返回 `NULL` / `false` 等异常值；
- 新版本 PHP：直接抛 `TypeError`，脚本中断。

所以**数组绕过是否成立，强依赖 PHP 版本和具体函数**。

### 典型代码

```php
<?php
$a = $_GET['a'];
$b = $_GET['b'];

if ($a !== $b && md5($a) === md5($b)) {
    echo $flag;
}
```

如果这是旧版本 PHP 的经典环境，可以尝试：

```text
?a[]=1&b[]=2
```

利用思路是：

- `$a !== $b`：两个数组内容不同，条件成立；
- `md5($a)`、`md5($b)`：旧环境里可能都返回 `NULL`；
- `NULL === NULL`：成立。

### 为什么这招现在不一定能用

这个点在老题里非常常见，但在现代环境里不能直接默认成立。

- `md5()` 的官方签名是 `md5(string $string, bool $binary = false): string`；
- 现代 PHP 对内部函数的参数类型检查更严格；
- 在 PHP 8+ 里，给 `md5()` 传数组通常会抛出 `TypeError`，而不是像老版本那样仅警告并返回异常值。

所以做题时一定先判断：

- 题目运行的 PHP 版本；
- 是否关闭了错误显示；
- 是否有 `try/catch` 或其他逻辑吞掉异常；
- 使用的是哪一个函数。

### 常见可绕函数/场景

老题里常见的数组绕过点有：

- `md5($_GET['a'])`
- `sha1($_GET['a'])`
- `strcmp($_GET['a'], $password)`
- `preg_match($pattern, $_GET['a'])`

其中典型题型包括：

#### 1. hash 函数绕过

```php
if (sha1($a) === sha1($b))
```

旧环境可尝试：

```text
?a[]=1&b[]=2
```

#### 2. 字符串函数绕过

```php
if (strcmp($_GET['user'], $password) == 0)
```

如果 `user` 被传成数组，旧版本/特定环境下 `strcmp()` 可能返回异常值，进而被宽松比较误判。

#### 3. 正则函数绕过

```php
if (!preg_match('/admin/', $_GET['user']))
```

把 `user` 传成数组后，某些老环境会让正则函数执行异常，从而绕过校验。

### 做题时的判断关键词

看到下面这些情况，要马上试一下数组输入：

- 参数来自 `$_GET` / `$_POST`；
- 代码直接把参数传给字符串函数、hash 函数、正则函数；
- 没有 `is_array()`、`is_string()` 之类的检查；
- 题目是老靶场、老比赛、老博客题解。

常用测试姿势：

```text
?a[]=1
?a[]=1&b[]=2
?user[]=admin
```
