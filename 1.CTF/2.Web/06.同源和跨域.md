# 同源和跨域

## 同源策略（SOP）

同源策略是一种安全机制，浏览器通过它来限制不同源之间的交互。如果它们具有相同的协议、主机和端口，那么两个URL被认为是同源的。例如：

- `http://example.com/page1` 和 `http://example.com/page2` 是同源的。
- `http://example.com` 和 `https://example.com` 不是同源的。
- `http://example.com` 和 `http://sub.example.com` 不是同源的。

同源策略限制了以下几种类型的交互：

- DOM访问：一个页面不能访问另一个页面的DOM。
- Cookie访问：一个页面不能访问另一个页面的Cookie。
- AJAX请求：一个页面不能向另一个域发送AJAX请求。
- 其他资源访问：一个页面不能访问另一个域的资源，如图片、脚本等。

同源策略的目的是保护用户的隐私和安全，防止恶意网站窃取用户数据或执行未经授权的操作。

> AJAX请求是指通过JavaScript发送的HTTP请求，通常用于与服务器进行异步通信。由于同源策略的限制，AJAX请求只能发送到与当前页面同源的服务器。

## 跨域资源共享（CORS）

跨域资源共享（CORS）是一种机制，允许服务器指定哪些源可以访问其资源。通过在HTTP响应头中设置`Access-Control-Allow-Origin`，服务器可以允许特定的域访问其资源，设置`Access-Control-Allow-Methods`来指定允许的HTTP方法，设置`Access-Control-Allow-Headers`来指定允许的请求头，设置`Access-Control-Allow-Credentials`来指定是否允许携带凭据（如Cookie）。例如：

```http
Access-Control-Allow-Origin: https://allowed.example.com
Access-Control-Allow-Methods: GET,POST,OPTIONS,PUT,DELETE
Access-Control-Allow-Headers: Content-Type,Authorization
Access-Control-Allow-Credentials: true
```

> 例如在aaa.com中发送一个AJAX请求，想要访问bbb.com上的资源，如果bbb.com的服务器响应中包含`Access-Control-Allow-Origin: https://aaa.com`，则表示允许aaa.com访问其资源，aaa.com就可以成功获取数据。

## 跨站请求伪造（CSRF）

### 概念

跨站请求伪造（CSRF）是一种攻击方式，攻击者诱使用户在已认证的情况下执行不想要的操作。攻击者通常会创建一个恶意网站，当用户访问该网站时，利用用户的登录状态向受信任的网站发送请求。

1. 用户登录到银行网站，保持登录状态。
2. 攻击者创建一个恶意网站，包含一个表单或AJAX请求，指向银行网站的转账接口。
3. 用户访问恶意网站，触发请求，访问银行网站，并携带用户的认证信息进行恶意操作。

例如：

银行网站的转账接口：

```http
POST /transfer HTTP/1.1
Host: bank.com
Content-Type: application/x-www-form-urlencoded
Cookie: session=abcdef123456

amount=1000&count=12345
```

攻击者的恶意网站：

```html
...
<form action="http://bank.com/transfer" method="POST" id="hack">
    <input type="hidden" name="amount" value="1000">
    <input type="hidden" name="count" value="12345">
</form>
...
<script>
    document.getElementById('hack').submit();
</script>
...
```

当用户访问恶意网站时，浏览器会自动提交表单，发送一个POST请求到银行网站的转账接口，并携带用户的认证信息，导致用户的资金被转移。

### 解决方法

1. **CSRF Token**：在每个表单中包含一个唯一的CSRF token，服务器验证该token以确保请求的合法性。
2. **SameSite Cookie**：设置Cookie的SameSite属性为Strict或Lax，限制跨站请求携带Cookie。Strict表示完全禁止跨站请求携带Cookie，Lax表示允许部分跨站请求携带Cookie。
3. **验证Referer头**：服务器检查请求的Referer头，确保请求
4. **验证码**：在敏感操作前要求用户输入验证码，增加攻击难度。
