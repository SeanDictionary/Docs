# XSS

XSS (Cross-Site Scripting) 是一种常见的网络安全漏洞，攻击者通过在受信任的网站上注入恶意脚本代码，使得用户在访问该网站时执行这些恶意代码，从而窃取用户的敏感信息、劫持用户会话、篡改网页内容等。

## XSS的类型

### 反射型XSS（Reflected XSS）

**非持久型XSS**

反射型XSS是指攻击者将恶意脚本代码作为输入参数发送到服务器，服务器将这些参数直接反射回用户的浏览器中执行。这种类型的XSS通常发生在搜索框、表单提交等场景中。

这种攻击方式的注入代码是从目标服务器通过错误信息、搜索结果等等方式“反射”回来的：发出请求时，XSS代码出现在URL中，作为输入提交到服务器端，服务器端解析后响应，XSS代码随响应内容一起传回给浏览器，最后浏览器解析执行XSS代码。而称为非持久型XSS，则是因为这种攻击方式具有一次性，由于代码注入的是一个动态产生的页面而不是永久的页面，因此这种攻击方式只在点击链接的时候才产生作用。

例如：攻击者通过电子邮件等方式给别人发送带有恶意脚本代码参数的 URL，当 URL 地址被打开时，注入脚本被传输到目标服务器上，然后服务器将注入脚本“反射”到受害者的浏览器上，特有的恶意代码参数被 HTML 解析、执行。

非持久型 XSS 漏洞攻击的四大特点：
- 即时性。不经过服务器存储，直接通过 HTTP 的 GET 和 POST 请求就能完成一次攻击，拿到用户隐私数据
- 攻击者需要诱骗点击
- 反馈率低，所以较难发现和响应修复
- 盗取用户敏感保密信息

防止出现非持久型 XSS 漏洞的五大措施：
- Web 页面渲染的所有内容或者渲染的数据都必须来自于服务端
- 尽量不要从 URL，document.referrer，document.forms 等这种 DOM API 中获取数据直接渲染
- 尽量不要使用 `eval`, `new Function()`, `document.write()`, `document.writeln()`, `window.setInterval()`, `window.setTimeout()`, `innerHTML`, `document.creteElement()` 等可执行字符串的方法
- 如果做不到以上几点，也必须对涉及 DOM 渲染的方法传入的字符串参数做 escape 转义
- 前端渲染的时候对任何的字段都需要做 escape 转义编码

### 存储型XSS（Stored XSS）

**持久型XSS**

存储型XSS是指攻击者将恶意脚本代码存储在服务器的数据库中，当用户访问包含这些恶意代码的页面时，浏览器会执行这些代码。这种类型的XSS通常发生在用户评论、论坛发帖等场景中。

这种攻击多见于论坛，攻击者在发帖的过程中，将恶意脚本连同正常信息一起注入到帖子的内容之中。随着帖子被论坛服务器存储下来，恶意脚本也永久地被存放在论坛服务器的后端存储器中。当其它用户浏览这个被注入了恶意脚本的帖子的时候，恶意脚本则会在他们的浏览器中得到执行，从而受到了攻击。存储型XSS更具有隐蔽性，带来的危害也更大，除非服务器能完全阻止注入，否则任何人都很有可能受到攻击。

持久型 XSS 的三大特点：
- 持久性，植入在数据库中
- 危害面广，甚至可以让用户机器变成 DDoS 攻击的肉鸡
- 盗取用户敏感私密信息

防止持久型 XSS 漏洞的三大措施：
- 后端在入库前应该选择不相信任何前端数据，将所有的字段统一进行转义处理
- 后端在输出给前端数据统一进行转义处理
- 前端在渲染页面 DOM 的时候应该选择不相信任何后端数据，任何字段都需要做转义处理

### DOM型XSS（DOM-based XSS）

DOM型XSS的攻击方式是通过修改页面的 DOM 结构来注入恶意脚本代码，这些代码在用户浏览器中执行。攻击者可以通过 URL 参数、表单输入等方式将恶意代码注入到页面中，然后利用 JavaScript 操作 DOM 来执行这些代码。

DOM 型 XSS 的三大特点：
- 通过修改 DOM 结构来注入恶意代码
- 代码注入的来源是 URL 参数、表单输入等
- 代码在用户浏览器中执行

防止 DOM 型 XSS 漏洞的三大措施：
- 前端在渲染页面 DOM 的时候应该选择不相信任何后端数据，任何字段都需要做转义处理
- 前端在使用 URL 参数、表单输入等数据时应该进行严格的验证
- 前端在操作 DOM 时应该避免使用可执行字符串的方法，例如 `eval`, `new Function()`, `document.write()`, `document.writeln()`, `window.setInterval()`, `window.setTimeout()`, `innerHTML`, `document.creteElement()` 等，对传入的字符串参数做 escape 转义
