# 并发

## 进程

进程就是正在运行的程序的实例。它是操作系统分配资源的基本单位。可以理解为一个“活动的容器”，里面装了程序代码、运行数据和操作系统分配的资源。每个进程都有自己的内存空间、文件描述符和系统资源。进程之间相互独立，互不干扰。操作系统通过调度算法来管理多个进程的执行，使得它们能够共享CPU时间。

**组成** ：

1. **代码段** （Text Segment）：程序指令。
2. **数据段** （Data Segment）：全局变量、静态变量。
3. **堆** （Heap）：动态分配的内存。
4. **栈** （Stack）：函数调用、局部变量。
5. **进程控制块（PCB）** ：存储进程信息，包括：
    - 进程ID
    - 程序计数器（PC）
    - 寄存器
    - 内存分配信息
    - 打开的文件列表
    - 调度信息（优先级、状态等）

进程的作用：

- **资源隔离**：不同进程的地址空间独立，防止互相干扰。
- **多任务执行**：操作系统可以在多个进程间切换，让CPU“同时”运行多个任务。
- **安全性**：进程崩溃不会直接影响其他进程。

进程有以下这些状态：

1. **新建（New）** ：刚创建还没调度执行。
2. **就绪（Ready）** ：可以运行，但等待CPU调度。
3. **运行（Running）** ：正在CPU上执行。
4. **阻塞/等待（Blocked/Waiting）** ：等待某个事件或资源。
5. **终止（Terminated）** ：执行完成或被操作系统结束。

进程和线程的比较：

| 特性         | 进程                                | 线程                   |
| ------------ | ----------------------------------- | ---------------------- |
| 地址空间     | 独立                                | 共享进程地址空间       |
| 资源         | PCB、内存、文件描述符               | 栈、寄存器、程序计数器 |
| 创建销毁开销 | 大                                  | 小                     |
| 切换开销     | 大                                  | 小                     |
| 通信         | 需要IPC（管道、共享内存、消息队列） | 内存共享，通信方便     |

## 线程

线程是进程中的一个执行单元，是CPU调度的基本单位。一个进程可以包含多个线程，这些线程共享进程的资源（如内存、文件描述符等），同时每个线程有自己的栈和寄存器。线程之间的切换比进程更快，因为它们共享地址空间，不需要切换内存映射。

线程的作用：

- **提高并发性**：多个线程可以同时执行不同的任务，提高程序的响应性和效率。
- **资源共享**：线程共享进程的资源，方便数据交换和通信。
- **降低开销**：线程的创建和销毁开销较小，线程切换比进程更快。

线程通常由以下部分组成：

1. **线程ID**：唯一标识一个线程。
2. **程序计数器（PC）**：指示线程正在执行的指令地址。
3. **寄存器**：保存线程的运行状态。
4. **栈**：每个线程有自己的栈，用于存储函数调用和局部变量。
5. **线程控制块（TCB）**：存储线程信息，包括线程ID、状态、优先级等。

和进程类似，线程同样有以下状态：

1. **新建（New）** ：刚创建还没调度执行。
2. **就绪（Ready）** ：可以运行，但等待CPU调度。
3. **运行（Running）** ：正在CPU上执行。
4. **阻塞/等待（Blocked/Waiting）** ：等待某个事件或资源。
5. **终止（Terminated）** ：执行完成或被操作系统结束。

线程的使用场景：

- **多任务处理**：如同时处理多个用户请求。
- **并行计算**：如在多核CPU上同时执行多个计算任务。
- **异步操作**：如在后台执行长时间运行的任务，保持界面响应。
- **资源共享**：如多个线程访问同一数据结构，需注意同步问题。

线程的同步问题：

- **互斥锁（Mutex）**：保证同一时间只有一个线程访问共享资源。
- **读写锁（Read-Write Lock）**：允许多个线程同时读，但写操作需要独占访问。
- **条件变量（Condition Variable）**：线程等待某个条件满足时被唤醒。
- **信号量（Semaphore）**：控制访问资源的线程数量。
- **死锁**：多个线程互相等待对方释放资源，导致程序无法继续执行。
- **竞态条件**：多个线程同时访问共享资源，导致结果不确定。
- **线程安全**：设计程序时确保多线程环境下的正确性，避免数据不一致和崩溃。

所以在线程编程中，必须注意线程同步和资源管理，以确保程序的正确性和效率。对于 **非原子操作** 需要添加锁来保证数据一致性。但同时也会引入额外的 **性能开销** 、**线程阻塞** 和 **死锁风险**，因此需要谨慎设计和使用线程同步机制。

> **原子操作** 是指不可分割的操作，要么全部执行成功，要么全部不执行，不会被线程调度打断。常见的原子操作包括基本数据类型的读写、某些CPU指令（CAS...）等。对于非原子操作，需要使用锁等同步机制来保证线程安全。

> **死锁** 是指两个或多个线程互相等待对方释放资源，导致程序无法继续执行。例如 Thread1 被 Lock1 及 Lock2 锁住，等待其他线程释放 Lock2，才能释放 Lock1；Thread2 被 Lock2 及 Lock1 锁住，等待其他线程释放 Lock1，才能释放 Lock2。这样就形成了死锁，程序无法继续执行。
> 解决方案例如：统一多线程的锁顺序、使用定时锁、避免嵌套锁、使用死锁检测算法等。

## 协程

协程是一种轻量级的线程，也被称为用户态线程。它们在单线程内实现多任务并发，通过协作式调度来切换执行。协程的切换由程序员控制，而不是由操作系统调度器自动切换。协程可以在执行过程中主动让出控制权，允许其他协程运行，从而实现高效的并发。

协程的作用：

- **高效的并发**：协程切换开销小，可以在单线程内实现大量的并发任务。
- **简化异步编程**：协程可以使用同步的编程风格来编写异步代码，避免回调地狱。
- **资源节约**：协程不需要操作系统分配独立的内存空间，节约资源。

协程的使用场景：

- **I/O密集型任务**：如网络请求、文件读写等，可以通过协程实现高效的并发处理。
- **高并发服务器**：如Web服务器，可以使用协程处理大量的客户端连接。
- **异步编程**：如在GUI应用中，使用协程可以保持界面响应，同时执行长时间运行的任务。

协程的实现方式：

- **生成器**：通过生成器函数实现协程，使用 `yield` 关键字来切换执行。
- **async/await**：现代编程语言（如Python、JavaScript）提供了 `async` 和 `await` 关键字来简化协程的编写和使用。

协程的优缺点：

- **优点**：
    - 轻量级，切换开销小。
    - 简化异步编程，代码更清晰。
    - 资源节约，不需要独立的内存空间。
- **缺点**：
    - 需要程序员手动控制切换，容易出错。
    - 不适合CPU密集型任务，因为它们无法利用多核CPU的优势。
    - 可能导致回调地狱，如果不合理使用协程，代码可能变得难以维护。
      总的来说，协程是一种高效的并发编程模型，适用于I/O密集型任务和异步编程，但需要谨慎使用以避免代码复杂性和性能问题。

> **异步和协程**：异步是一种执行模型，表示调用不会阻塞当前线程；协程是一种在用户态实现的轻量级执行单元，通过挂起和恢复来实现异步执行。在 Python 或 Go 中，协程是实现异步编程的主要方式之一，但异步本身不等于协程，还可以通过线程或回调实现。

## 调度

调度是操作系统管理多个线程执行的机制。调度器负责决定哪个进程或线程获得CPU时间，以及何时切换到另一个进程或线程。调度算法根据不同的策略来分配CPU时间，以实现公平性、效率和响应性。

常见的调度算法包括：

- **先来先服务（FCFS）**：按照进程到达的顺序进行调度，简单但可能导致长时间等待。
- **短作业优先（SJF）**：优先调度执行时间最短的进程，效率高但可能导致长作业饥饿。
- **优先级调度（Priority Scheduling）**：根据进程的优先级进行调度，优先级高的进程先执行，但可能导致低优先级进程饥饿。
- **轮转调度（Round Robin）**：每个进程分配一个固定的时间片，轮流执行，公平但可能增加上下文切换开销。
- **多级反馈队列（Multilevel Feedback Queue）**：根据进程的行为动态调整优先级，适合多种类型的进程。

调度的目标是最大化CPU利用率、最小化等待时间和响应时间，同时确保系统的公平性和稳定性。不同的调度算法适用于不同的应用场景，操作系统通常会根据当前系统负载和进程特性来选择合适的调度算法。
