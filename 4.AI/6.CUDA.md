# CUDA

## 设计思路

CUDA 采用 SIMT 式的并行计算模型，允许在 GPU 上同时执行大量线程。每个线程都有自己的寄存器和本地内存，但共享全局内存和常量内存。CUDA 编程模型包括以下几个关键概念：

1. **线程（Thread）**：CUDA 中的基本执行单元，每个线程执行相同的代码，但可以访问不同的数据。线程通过线程索引（threadIdx）来区分。
2. **线程块（Thread Block）**：线程的集合，线程块中的线程可以共享数据和同步操作。每个线程块有一个唯一的索引（blockIdx），用于区分不同的线程块。
3. **网格（Grid）**：线程块的集合，网格中的线程块可以在 GPU 上并行执行。网格的大小由线程块的数量和每个线程块中的线程数量决定。

> [!TIP]
> 昇腾显卡 采用 SIMD 式的并行计算模型，允许在 NPU 上通过一次指令同时操作多个数据

GPU 并不是一个独立运行的计算平台，而需要与 CPU 协同工作，可以看成是 CPU 的协处理器，因此当我们在说 GPU 并行计算时，其实是指的基于 CPU + GPU 的异构计算架构。在异构计算架构中，CPU 所在位置称为主机端（host），而GPU所在位置称为设备端（device）

## 硬件结构

**SM**: Streaming Multiprocessor，是 GPU 中的基本处理核心，包含多个 CUDA core、共享内存、寄存器等资源。SM 是 GPU 硬件调度任务的最小单元，也是 GPU 物理架构的核心基本块。AMD 对应叫计算单元 CU（Compute Unit），二者设计理念完全一致，行业通用 SM 代指这一核心模块。

**SP**：Steam Processor，又称 CUDA Core，一个 SM 中包含多个 SP，多个 SP 按使用场景分组，负责不同dtype计算

**warp**：warp 是GPU硬件调度和执行的最小物理单元，由硬件自动生成，固定包含32个Thread。

**L1**：L1缓存，位于SM内部，和L2同为片上内存，读写速度更快

**L2**：L2缓存，SM间共享，和L1同为片上内存，读写速度更快

**显存位宽**：BusWidth，显存位宽指的是在一个时间周期内可以传输多少的比特

**显存频率**：ClockRate，频率指的是内存在一秒内可以经历多少的时间周期

**显存带宽**：BandWidth，显存带宽是 GPU 的一项重要性能指标，它反映了 SM 在计算的过程中从显存中读写数据的速度，单位是 (GB/s)。显然，由于在 SM 中还存在运算指令执行过程，所以实际的程序利用的有效带宽并不能完全达到显存带宽提供的理论上限。了解显存带宽的指导意义在于，可以帮助我们评估算法的硬件利用率，如果利用率太低，那么就需要考虑如何优化算法；显存可以通过位宽和频率计算得到：

$$
BandWidth = 2 \times ClockRate \times (BusWidth/8)
$$

### 分支发散

任何时刻，warp 中包含的线程必须执行同一条指令，但是不同线程处理数据不同，如果代码中存在分支、循环等控制流，则会出现线程空转的情况，即例如：

```c
if (threadIdx.x < 16) {
    // do something
} else {
    // do something else
}
```

由于 warp 中包含 32 个线程，前 16 个线程执行第一条指令时，后 16 个线程在执行第一条指令时空转；后 16 个线程在执行第二条指令时，前 16 个线程在执行第二条指令时空转，从而降低了 GPU 的计算效率。

常见空转的处理方法：让同一个warp中的线程走同一个分支

## 数据处理

在kernel侧的性能评价中，数据的读写搬运耗时是会占用很大一部分性能开销的，多次独立的读写事务就会造成后续计算的阻塞，从而影响到整体的效率和性能

### 访存合并

看一个典型的逐元素加法操作：C[i] = A[i] + B[i]。

- 计算量：1 次加法。
- 访存量：读取 A、读取 B、写入 C。共计 3 次显存操作（假设单精度浮点，每次 4 字节）。 此时，计算访存比 = 1 FLOP / 12 Bytes ≈ 0.08 FLOP/Byte。 而主流 GPU 的理论峰值计算访存比通常在 10~20 FLOP/Byte 以上。

以 NVIDIA GPU 架构为例，L2 缓存与显存控制器之间的最小传输单元通常为 32 字节。当 SM 发出一次全局内存访问请求时，硬件会尝试将同一 Warp 的所有请求**合并**成尽可能少的事务，即 coalescing。

每一次操作的话都只能处理一个float，也就是4 Byte。如果理想情况下，该warp中的所有线程的数据读写都是连续的，那硬件就会合并成一个完整的128字节请求或者4次32字节请求。如果warp中线程的数据读写都是非离散的，则会独立成最差32次的独立事务。

### 隐藏访存延迟

为了隐藏访存延迟，主要的核心思路也是尽可能让读写和计算能重叠并行，以减少内存等待时间

CUDA 中以 wrap 为调度单位，当一个 wrap 在处于读写等待的过程中，硬件会调用其余已经准备号的 wrap 进行计算任务，以隐藏等待时间。

> [!TIP]
> 昇腾显卡 采用双缓冲 double buffer 机制，硬件会自动建立两个 Buffer，通过两个 Buffer 交替承担数据搬运和计算，使数据搬运与计算可以重叠，从而来隐藏读写的时间开销。
> 需要注意的一点是昇腾的这种流水执行可以在同一个 AI Core 上，把不同阶段/不同数据块组织成流水。
> 而CUDA中因为一个SM上可以驻留多个warp，当某个 Warp 因访存等原因暂时无法继续执行时，SM 的 Warp Scheduler 可以选择另一个就绪 Warp 执行，从而隐藏访存延迟。

### 网格跨步循环 Grid-Stride Loop

例如常见的通用配置

```c++
int threadsPerBlock = 256;
int blocksPerGrid = (N + threadsPerBlock - 1) / threadsPerBlock;
add_kernel<<<blocksPerGrid, threadsPerBlock>>>(d_A, d_B, d_C, N);
```

其中 Block 数是根据数据量的大小来动态调节的，每个线程处理固定的数据量

换一种思路，原先是线程处理固定的数据量，通过 block 划分的数据块界限来做判断。如果每个线程不是处理数据块的全部内容，而是循环处理所有数据块的第一个数据，于是就可以使用固定数量的线程来处理任意大小的数据量

```c++
int threadsPerBlock = 256;
int blocksPerGrid = 128 * 2;   //  SM 数量 × 若干倍，而非 N/256
add_kernel_v2<<<blocksPerGrid, threadsPerBlock>>>(d_A, d_B, d_C, N);
```

> 有点神秘，只是解耦了线程数和数据量的关系，以及理解上有点变化。实际上对于运行没有额外影响
